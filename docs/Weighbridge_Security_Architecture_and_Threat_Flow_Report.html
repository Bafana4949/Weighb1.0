6. Security Risk Gap Analysis & Architectural Remediation
Executive Finding

THE SINGLE BIGGEST ARCHITECTURAL VULNERABILITY:

Universal Static Shared API Key (SITE_DAEMON_API_KEY) Combined with Unauthenticated Local MQTT Broker (allow_anonymous: true).

6.1 Vulnerability Deep-Dive & Blast Radius Analysis

In the current implementation, every edge daemon instance across all remote weighbridge sites uses a single, shared static secret passed in the x-site-api-key HTTP header to authenticate against cloud endpoints (such as /api/transactions/reconcile, /api/incidents, and /api/bookings/active).

// apps/web/src/lib/api.ts (Lines 59-65) - CURRENT VULNERABLE PATTERN: export async function requireSiteOrRole(request: NextRequest, roles: UserRole[]) { const configured = process.env.SITE_DAEMON_API_KEY; const key = request.headers.get("x-site-api-key"); // CRITICAL: A single global key authenticates ANY site without validating siteId bindings! if (configured && key && key === configured) return { error: null, actor: { type: "site" as const, id: "edge-daemon" } }; ... }

Exploitation Path & Consequence:

  • 1. Physical Compromise of One Remote Edge Gateway: An adversary gaining physical or local LAN access to a single scale site extracts SITE_DAEMON_API_KEY from config.yaml or environment variables.
  • 2. Fleet-Wide Impersonation: Because the cloud API does not cryptographically bind the API key to a specific site_id, the compromised key allows the attacker to forge weighbridge transactions, inject false calibration states, or exfiltrate scheduled bookings for every mine and weighbridge in the entire enterprise network.
  • 3. Field Actuator Overwrite via Anonymous MQTT: Because Mosquitto runs with allow_anonymous true on ports 1883 and 9001 without TLS, an attacker on the local LAN can inject @CMD:GATE_OPEN commands directly into the broker, opening security boom gates without cloud authorization.

6.2 Recommended Target Architecture (Zero-Trust Edge Identity)

To achieve defense-in-depth, replace the universal static key with Per-Site Asymmetric Ed25519 Key Pairs and mTLS (Mutual TLS):

Component Current Vulnerable State Target Remediated State Implementation Effort
Edge-to-Cloud AuthN Single shared SITE_DAEMON_API_KEY string. Per-Site Ed25519 Request Signing: Each edge gateway signs HTTP payload + timestamp with private key; cloud validates against public key mapped to site.id. Medium (2 Days)
MQTT Message Security Plaintext TCP on 1883, allow_anonymous true. MQTT over TLS (Port 8883): ACL rules restricting topics by client certificate; anonymous access disabled. Low (1 Day)
Debug Endpoint Exposure /api/debug and /api/seed-rbac publicly reachable. Gated / Removed: Remove debug routes from production builds; protect seeding with requirePlatformSuperAdmin(). Low (1 Hour)
Dependency Hardening Legacy xlsx v0.18.5 with known prototype pollution. Upgrade: Migrate to exceljs or patched SheetJS v0.20.2+; isolate parsing in worker sandbox. Low (4 Hours)
Compliance Note: Implementing per-site asymmetric key signing satisfies ISO 27001 (A.10.1 Cryptographic Controls) and NIST SP 800-82 (Guide to Industrial Control Systems Security).
